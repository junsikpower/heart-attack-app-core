# 심박수 측정 알고리즘 개선 논의 요약

이 문서는 이전 AI와의 대화를 통해 도출된 심박수 측정 알고리즘의 문제점 분석과 개선 방안을 정리한 요약본입니다.

## 1. 문제 현상 분석
- **스파이크 노이즈 (Spike Noise):** 단일 프레임 만에 심박수가 급격히 튀는 현상 (예: 85 -> 180 BPM).
- **계단 등반형 노이즈 (Drift Noise):** 손가락 압력 변화 등으로 인해 수치가 서서히 정교하게 상승하는 현상 (예: 100 -> 105.8 -> 112.5 BPM).
- **기계적 격자 고착 (Grid Lock):** 카메라 30 FPS 샘플링(33.33ms)의 특성상, 노이즈 수치가 특정 수치(112.5, 180.0 등)의 소수점까지 일치하는 현상.
- **isGoodSignal의 한계:** 패키지 내부의 신호 품질 판정 로직이 광학적 안정성만 체크하여 기계적 노이즈를 정상 신호로 오인함.

## 2. 주요 발견 사항 (통찰)
- **소수점 동결 (Zero Variance):** 기계적 노이즈는 소수점 아래까지 변화가 전혀 없으나, 실제 인간의 심박수는 심박 변이도(HRV)로 인해 미세하게 출렁임.
- **정상 상태의 역설:** 측정 자세가 매우 안정적일 경우, 정상 데이터도 수 초간(약 5초 이상) 소수점까지 고정될 수 있음(예: 85.714286). 따라서 '무변이' 자체를 에러의 유일한 잣대로 삼으면 정상 데이터를 자폭 폐기할 위험이 있음.

## 3. 최종 교정된 3단계 방어 로직 (Proposed Logic)
소프트웨어가 모든 물리적 실수를 완벽히 걸러낼 수 없음을 인정하고, 현실적으로 '사용할 만한' 수준으로 보정하는 3단계 전략을 채택함.

### 1단계: 돌발 스파이크 즉시 제거
- **조건:** `abs(현재BPM - 직전BPM) >= 20`
- **처리:** 1프레임 만에 20 BPM 이상 변동 시 기계적 노이즈로 간주하고 즉시 폐기. 화면 수치는 직전 값을 유지(Hold).

### 2단계: 점진적 오류의 지연 처리 (EMA 늪)
- **조건:** 변화량이 20 BPM 미만인 상승/하락.
- **처리:** 일단 통과시키되, **지수 이동 평균(EMA) 필터**를 강화하여 반영 속도를 늦춤.
  - 예: `_lastFilteredBpm = (_last * 0.90) + (current * 0.10)`
- **효과:** 가짜 수치가 들어와도 화면 수치가 매우 느리게 올라가므로, 유저가 자세를 고쳐 잡을 시간을 벌어줌.

### 3단계: 장기 오류 발생 시 시스템 리셋 (타임아웃)
- **조건:** 노이즈로 인해 데이터가 연속 90프레임(약 3초) 이상 폐기되어 화면이 얼어붙은 경우.
- **처리:** 시스템을 `0.0`으로 초기화하고 유저에게 가이드 메시지("손가락을 가만히 대어주세요")를 표시.

## 4. 향후 구현 방향
- `HeartRateProvider` 또는 관련 서비스 레이어에서 위 3단계 로직을 구현하여 카메라 기반 심박수 측정의 신뢰도를 높임.
- 정상 범위 내의 소수점 고정 데이터를 보호하면서도, 급격한 노이즈만 효율적으로 차단하는 것이 핵심임.
